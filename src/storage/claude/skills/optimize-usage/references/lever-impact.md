# Lever impact

One number per lever, 0-100: how much degrading this lever degrades the final deliverable. Session model = 100 is the anchor — never step it lightly.

| Lever | Impact | Why |
|---|---|---|
| Session model | 100 | Defines the entire solution space — plan, scope, tests, review standards. Every downstream token executes its decisions, so its errors compound through the whole ticket. Nothing gates it. Independent Terminal-Bench 4.0 (Artificial Analysis / Vals.ai, 2026-10): Opus 5.5 59.6 / 65.2, Sonnet 5.5 63.6 / 64.1, Fable 5.1 52.0 / 58.1. Fable 5.1 trails Opus 5.5 on both boards at 2.15x the cost per task, so fable→opus is a free step on coding evidence. The 100 covers the full span down to haiku. |
| Review model | 60 | The last gate; its misses ship. Strong review is also what makes cheap workers safe — degrading it weakens every other lever's safety argument. |
| Session effort | 50 | Same blast radius as session model, but shallower per step: published data shows max and xhigh equivalent — on Opus 5.5, independent Terminal-Bench 4.0 is 59.6 at both xhigh and max (Artificial Analysis, 2026-10) — while max costs 3.29x high per task (Artificial Analysis, 2026-09-28). Medium, Opus 5.5's default, is mixed: CursorBench 4.0 drops from 57.8 at max to 52.5, FrontierCode holds (54.6 vs 54.4), and it costs 0.74x high. Steps here still move quality less than model swaps. On Fable 5.1 Anthropic says low or medium matches or beats Fable 5 (2026-09). |
| Review effort | 35 | Thoroughness is the whole job of review; lower effort trims exactly the double-checking the role exists for. |
| Worker model | 30 | Runs every task card, test-verified and judgment alike. Cards are fully specified inside a solved problem and every diff passes two gates, but a model that does exactly what it was told misses what a card leaves unstated, and no test catches that. A month on sonnet showed no recorded quality drop. `deepseek-flash` serves DeepSeek-V4.1-Flash (2026-09-10); `deepseek-v4-pro` serves DeepSeek-V4-Pro-0813. Independent Terminal-Bench 4.0 (Artificial Analysis / Vals.ai, 2026-10): flash 26.8 / 19.7, pro — / 14.1, Sonnet 5 — / 9.6, against Opus 5.5 59.6 / 65.2 and Sonnet 5.5 63.6 / 64.1. DeepSeek's own runs (Terminal-Bench 2.1 flash 90.6, DeepSWE 74.2) put flash level with Opus 5; independent coding runs put it 33-45 points behind, so vendor-run scores never rank this lever. Pro trails flash at 2.5x its cost per task, so flash dominates pro. Flash ranks above sonnet by user decision (2026-09-21), which still holds while `sonnet` binds Sonnet 5 (19.7 vs 9.6 on Vals.ai); Sonnet 5.5 at 0.62x beats flash by about 37 points. Haiku is dominated while the proxy is up. |
| Worker effort | 10 | Left at `inherit` deliberately — workers track session effort. Cards are scoped, and quality risk is bounded by the committed tests a worker iterates against rather than by a downstream gate. |
| Research fan-out model | 8 | Deep-research fan-out (dev-workflow Step 4.1): read-and-summarize online research every tier is saturated on. Output is intermediate and the parent session model synthesizes it, so a cheap model here is near-free — the safest fan-out to cheapen first. |
| Code fan-out model | 20 | Codebase-fit fan-out (dev-workflow Step 4.2): analyzes real code to claim placement and reuse that shape the plan. A wrong reuse claim is the classic failure that step exists to catch; adversarial verification gates it, but degrade more cautiously than research fan-out. |
| Review fan-out model | 45 | The finder subagents are where detection actually happens. A bug a finder misses is caught by nothing downstream — unlike a bad finding, which the disproof step filters — so this lever is asymmetric: cheapening it loses bugs silently. Below review model (60) only because the parent still frames the review, splits the units, and makes the final call. |
| Review fan-out effort | 25 | Same agents, shallower per step — the model-to-effort ratio the other paired levers show. Split personality: the disproof half gets one claim and is told to refute it, which is the most effort-insensitive work in the pipeline; open-ended finding is not. Rated for the finders. |
| Tester model | 50 | Writes the failing integration tests every worker is judged against, before any code exists. Asymmetric like review fan-out (45), and rated above it: a thin or shallow suite does not produce a bad result, it produces no result — the workers simply have less to satisfy, and nothing downstream notices. Cheapening this silently weakens the safety argument for every worker lever, so never step it to fund a worker step. On opus by user decision (2026-09-30): tests are the high-leverage point, and Opus 5.5 costs about the same per task as Sonnet 5 (1.00x vs 0.98x), so the step up is near cost-neutral. |
| Escalation model | 55 | Decides the escalations that would otherwise reach the user — a review gate's `escalate`, a worker call the parent cannot settle, a spec amendment in a chain — and at exit triage it decides which loose ends fold into the branch and which reach the user. Its escalations land unmediated and unreported, so a weak call becomes design direction nobody reviews; its folds at least pass back through the review gate. Rated above tester (50) for that reason and below review model (60) because it fires at most once per run outside escalations. |
| Scoping model | 45 | Builds the case file the brief, the solution, and the tier are decided from (dev-workflow Step 2). Its "is this needed" call and hypothesis verdicts are read as fact by the parent, and nothing downstream re-investigates — a missed root cause or a stale-doc claim taken at face value shapes the whole run. Below tester (50): the user still reads the brief built from it. |
| Scoping fan-out model | 12 | Read-and-report subagents the scoping agent splits its threads across when one context cannot hold them. The scoping agent holds the judgment and cites every claim at `file:line`, so a weak read surfaces as a missing citation rather than a wrong verdict. |
| Vault model | 15 (est.) | Also binds the ADR auditor (2026-09-27), which only reads and returns a verdict that reaches the vault through the user. The scribe writes knowledge-vault notes. Output is gated — the user approves a content summary before it lands — so errors are catchable, but notes are durable context for future sessions and quality drift compounds quietly. Unbenchmarked estimate (2026-07-21). On deepseek-flash by user decision (2026-09-30): the content-summary gate bounds the risk, and it removes this lever's Claude-limit draw. |
| Advisor model | 35 (est.) | Consulted at decision points — before committing to an approach, on a recurring error, before declaring done — so it moves plan quality, the thing the session model decides. It reaches only sessions and agents whose model ranks at or below it, and Claude decides when to call it, so its reach per run is unmeasured. Unbenchmarked estimate (2026-10-04).
