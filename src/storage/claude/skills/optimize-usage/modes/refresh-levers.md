# Refresh levers

Keeps the lever table complete and current. Run on request or after a Freeform pass that changed the landscape.

1. **Models and pricing.** Fetch the current catalog via the `claude-api` skill. Update the Options columns (add new models, drop retired ones) and refresh the family price ratios at current per-token rates — the price ratio (e.g. fable 2x opus) is the cost estimate for every row the benchmark cannot measure.
2. **Benchmarks.** Look up the latest published model and effort benchmarks; update the impact numbers and rationale in [lever-impact.md](../references/lever-impact.md) if the evidence moved.
3. **Re-measure lever cost.** Run the benchmark ([benchmark.md](../references/benchmark.md)) to get each session-lever position's per-unit-work cost ratio vs baseline — this replaces the old repricing, which could not see that a stronger model finishes in fewer turns. The cost column records these ratios directly; there is no slice-share term (decision 2026-07-21: the usage-capture pipeline was retired — its agent attribution could not measure per-lever slices, and it was not worth the maintenance). Levers 3-8 are not headless-benchmarkable yet — leave them at the Step 1 price-ratio estimate and tagged. Write the dated baseline artifact.
4. **New levers only.** Diff the repo config surface (`agents/*.md` frontmatter, dev-workflow dispatch files, `settings.json`) against the table; one `claude-code-guide` query catches newly added settings keys or env vars. Mechanical sweep, every cycle: `grep -E '^(model|effort):' agents/*.md` — every hit must appear in lever-state.json or the exclusion list (vault-scribe's pin slipped through a prose-only pass, 2026-07-21). Surface only levers that are genuinely new — never re-recommend anything on the exclusion list in levers.md.
5. **Update the table**: rows, options, cost and impact figures, the pie chart, and the `Last updated` date. Show the user the levers.md diff before writing — the table drives every future recommendation.
