# Lever impact

One number per lever, 0-100: how much degrading this lever degrades the final deliverable. Session model = 100 is the anchor — never step it lightly. A type has two levers, its model and its effort, rated separately; (est.) marks a number no benchmark separates.

| Lever | Impact | Why |
|---|---|---|
| Session model | 100 | Defines the entire solution space — plan, scope, tests, review standards. Every downstream token executes its decisions, so its errors compound through the whole ticket. Nothing gates it. Independent Terminal-Bench 4.0 (Artificial Analysis / Vals.ai, 2026-10): Opus 5.5 59.6 / 65.2, Sonnet 5.5 63.6 / 64.1, Fable 5.1 52.0 / 58.1. Fable 5.1 trails Opus 5.5 on both boards at 2.15x the cost per task, so fable→opus is a free step on coding evidence. The 100 covers the full span down to haiku. |
| Review model | 60 | The adversary, verify, and taste roles: the bug review's adversaries, whose misses ship, the verification lanes and the verdict, a miss in which nothing downstream catches, and the tasters. Strong review is also what makes cheap workers safe — degrading it weakens every other lever's safety argument. |
| Judgment model | 60 | The judgment and escalation roles: designs, syntheses, judges, and the calls that would otherwise reach the user, which land unmediated, so a weak call becomes design direction nobody reviews. |
| Session effort | 50 | Same blast radius as session model, but shallower per step: published data shows max and xhigh equivalent — on Opus 5.5, independent Terminal-Bench 4.0 is 59.6 at both xhigh and max (Artificial Analysis, 2026-10) — while max costs 3.29x high per task (Artificial Analysis, 2026-09-28). Medium, Opus 5.5's default, is mixed: CursorBench 4.0 drops from 57.8 at max to 52.5, FrontierCode holds (54.6 vs 54.4), and it costs 0.74x high. Steps here still move quality less than model swaps. On Fable 5.1 Anthropic says low or medium matches or beats Fable 5 (2026-09). |
| Critical code model | 45 (est.) | The hardest and contract roles, and code on a `## Critical` path: cross-cutting design, concurrency, subtle algorithms, where a weak model's mistakes are hardest to see, and the tests written before the code, which confine the coder. The bug review and the verdict gate the code, but a weak contract lets weak code through them. |
| General model | 40 | Every role no other type covers, the largest uncovered surface before the lever existed (one measured run: 31 of 62 agents, 46% of output tokens). |
| Review effort | 35 | Thoroughness is the whole job of an adversary and an auditor; lower effort trims exactly the double-checking the roles exist for. Driving a done-when line is effort-insensitive; auditing a diff against its intent is not. |
| Code model | 30 | Runs every code delegate. A brief is fully specified inside a solved problem and every diff passes the quality gate and the verdict, but a model that does exactly what it was told misses what a brief leaves unstated, and no test catches that. A month on sonnet showed no recorded quality drop. `deepseek-flash` serves DeepSeek-V4.1-Flash (2026-09-10); `deepseek-v4-pro` serves DeepSeek-V4-Pro-0813. Independent Terminal-Bench 4.0 (Artificial Analysis / Vals.ai, 2026-10): flash 26.8 / 19.7, pro — / 14.1, Sonnet 5 — / 9.6, against Opus 5.5 59.6 / 65.2 and Sonnet 5.5 63.6 / 64.1. DeepSeek's own runs (Terminal-Bench 2.1 flash 90.6, DeepSWE 74.2) put flash level with Opus 5; independent coding runs put it 33-45 points behind, so vendor-run scores never rank this lever. Pro trails flash at 2.5x its cost per task, so flash dominates pro. Flash ranks above sonnet by user decision (2026-09-21), made while `sonnet` bound Sonnet 5 (19.7 vs 9.6 on Vals.ai); it binds Sonnet 5.5 since 2026-10-04; Sonnet 5.5 at 0.62x beats flash by about 37 points. Haiku 5.5 is dominated: at max it scores 32.8 / 36.4, level with flash, but past a 100K-token prompt it costs 0.58x, about Sonnet 5.5's cost at half its score. Personal on flash by user decision (2026-10-21), for high volume, with review held on opus to carry the catch load; work on Sonnet 5.5 the same day. |
| Judgment effort | 30 (est.) | The judgment and escalation roles, shallower per step: the model-to-effort ratio the other paired levers show. |
| Critical code effort | 20 (est.) | The critical code roles, shallower per step, for the same reason. |
| General effort | 15 (est.) | Every role no other type covers, shallower per step. |
| Other family model | 15 (est.) | The second opinion from another model family: one of the bug review's two adversaries, the arena's cross-judge, and the decision trail's reviewer. Its value is that it fails differently from the author; a session-family model beside it carries the review. |
| Code effort | 10 | Left at `inherit` deliberately — workers track session effort. Briefs are scoped, and quality risk is bounded by the contract tests a worker iterates against rather than by a downstream gate. |
| Research model | 8 | The explore role: read-only search and source reading, work every tier is saturated on. Output is intermediate and a judgment-role agent or the session synthesizes it, so a cheap model here is near-free, the safest lever to cheapen first. |
| Research effort | 3 (est.) | Read-only search, shallower per step than its model. |
| Advisor model | 35 (est.) | Consulted at decision points — before committing to an approach, on a recurring error, before declaring done — so it moves plan quality, the thing the session model decides. It reaches only sessions and agents whose model ranks at or below it, and Claude decides when to call it, so its reach per run is unmeasured. Unbenchmarked estimate (2026-10-04).
