# Lever impact

One number per lever, 0-100: how much degrading this lever degrades the final deliverable. Session model = 100 is the anchor — never step it lightly.

| Lever | Impact | Why |
|---|---|---|
| Session model | 100 | Defines the entire solution space — plan, scope, tests, review standards. Every downstream token executes its decisions, so its errors compound through the whole ticket. Nothing gates it. Independent Terminal-Bench 4.0 (Artificial Analysis / Vals.ai, 2026-10): Opus 5.5 59.6 / 65.2, Sonnet 5.5 63.6 / 64.1, Fable 5.1 52.0 / 58.1. Fable 5.1 trails Opus 5.5 on both boards at 2.15x the cost per task, so fable→opus is a free step on coding evidence. The 100 covers the full span down to haiku. |
| Review model | 60 | The judgment, contract, and adversary roles: designs, syntheses, judges, the tests written before the code, and the bug review's adversaries, whose misses ship. Strong review is also what makes cheap workers safe — degrading it weakens every other lever's safety argument. |
| Session effort | 50 | Same blast radius as session model, but shallower per step: published data shows max and xhigh equivalent — on Opus 5.5, independent Terminal-Bench 4.0 is 59.6 at both xhigh and max (Artificial Analysis, 2026-10) — while max costs 3.29x high per task (Artificial Analysis, 2026-09-28). Medium, Opus 5.5's default, is mixed: CursorBench 4.0 drops from 57.8 at max to 52.5, FrontierCode holds (54.6 vs 54.4), and it costs 0.74x high. Steps here still move quality less than model swaps. On Fable 5.1 Anthropic says low or medium matches or beats Fable 5 (2026-09). |
| Review effort | 35 | The adversary role only. Thoroughness is the whole job of an adversary; lower effort trims exactly the double-checking the role exists for. |
| Worker model | 30 | Runs every code delegate. A brief is fully specified inside a solved problem and every diff passes the quality gate and the verdict, but a model that does exactly what it was told misses what a brief leaves unstated, and no test catches that. A month on sonnet showed no recorded quality drop. `deepseek-flash` serves DeepSeek-V4.1-Flash (2026-09-10); `deepseek-v4-pro` serves DeepSeek-V4-Pro-0813. Independent Terminal-Bench 4.0 (Artificial Analysis / Vals.ai, 2026-10): flash 26.8 / 19.7, pro — / 14.1, Sonnet 5 — / 9.6, against Opus 5.5 59.6 / 65.2 and Sonnet 5.5 63.6 / 64.1. DeepSeek's own runs (Terminal-Bench 2.1 flash 90.6, DeepSWE 74.2) put flash level with Opus 5; independent coding runs put it 33-45 points behind, so vendor-run scores never rank this lever. Pro trails flash at 2.5x its cost per task, so flash dominates pro. Flash ranks above sonnet by user decision (2026-09-21), made while `sonnet` bound Sonnet 5 (19.7 vs 9.6 on Vals.ai); it binds Sonnet 5.5 since 2026-10-04; Sonnet 5.5 at 0.62x beats flash by about 37 points. Haiku 5.5 is dominated: at max it scores 32.8 / 36.4, level with flash, but past a 100K-token prompt it costs 0.58x, about Sonnet 5.5's cost at half its score. Personal on flash by user decision (2026-10-21), for high volume, with review held on opus to carry the catch load; work on Sonnet 5.5 the same day. |
| Worker effort | 10 | Left at `inherit` deliberately — workers track session effort. Briefs are scoped, and quality risk is bounded by the contract tests a worker iterates against rather than by a downstream gate. |
| Research fan-out model | 8 | The explore role: read-only search and source reading, work every tier is saturated on. Output is intermediate and a judgment-role agent or the session synthesizes it, so a cheap model here is near-free, the safest fan-out to cheapen first. |
| Code fan-out model | 20 | The hardest role: `worker-agent` on cross-cutting design, concurrency, and subtle algorithms, the code where a weak model's mistakes are hardest to see. The bug review and the verdict gate it, but degrade it more cautiously than the code role. |
| Review fan-out model | 45 | The verify role: verification lanes and the verdict from a session that did not write the change. A bug a lane misses is caught by nothing downstream, so this lever is asymmetric: cheapening it loses bugs silently. Below review model (60) because the adversaries ran first. |
| Review fan-out effort | 25 | The verify role, shallower per step: the model-to-effort ratio the other paired levers show. Driving a done-when line is effort-insensitive; auditing a diff against its intent is not. |
| Escalation model | 55 | Decides the escalations that would otherwise reach the user — a hard call while cooking — and at exit triage it decides which loose ends fold into the branch and which reach the user. Its escalations land unmediated and unreported, so a weak call becomes design direction nobody reviews; its folds at least pass back through the review gate. Rated below review model (60) because it fires at most once per run outside escalations. |
| Advisor model | 35 (est.) | Consulted at decision points — before committing to an approach, on a recurring error, before declaring done — so it moves plan quality, the thing the session model decides. It reaches only sessions and agents whose model ranks at or below it, and Claude decides when to call it, so its reach per run is unmeasured. Unbenchmarked estimate (2026-10-04).
