# Refresh levers

Keeps the lever table complete and current. Run on request or after a Freeform pass that changed the landscape.

1. **Models and pricing.** Fetch the current catalog via the `claude-api` skill. Update the Options columns (add new models, drop retired ones) and the per-token prices quoted in the table. For the DeepSeek options (the code and other family types), also fetch api-docs.deepseek.com/quick_start/pricing, keep them matching the proxy's `DEEPSEEK_MODELS` allowlist. Record which model each name serves today: DeepSeek reroutes names between releases.
2. **Benchmarks.** Look up the latest published model and effort benchmarks, including DeepSeek's coding evals against the Claude tiers for the code type's ladder, for the version each name serves; update the impact numbers and rationale in [lever-impact.md](../references/lever-impact.md) if the evidence moved.
3. **Lever cost.** Take each option's cost per task from Artificial Analysis (artificialanalysis.ai, the Anthropic and DeepSeek provider pages), every figure from one Intelligence Index version, and record it as a ratio to Opus at high effort. Cost per task counts the extra turns and tokens a model spends, which per-token price ratios miss. The types reuse the row 1-2 ratios. There is no slice-share term (decision 2026-07-21: the usage-capture pipeline was retired — its agent attribution could not measure per-lever slices, and it was not worth the maintenance). The local benchmark was retired 2026-09-28: it measured what Artificial Analysis already publishes.
4. **New levers only.** Diff the repo config surface (`agents/*.md` frontmatter, skill files that dispatch agents, `settings.json`) against the table; one `claude-code-guide` query catches newly added settings keys or env vars. Mechanical sweep, every cycle: `grep -E '^(model|effort):' agents/*.md` — every hit must be an agent a type in lever-state.json lists under `agents`, or on the exclusion list (vault-scribe's pin slipped through a prose-only pass, 2026-07-21). Every role SKILL.md dispatches must map to a type in its table. A new type's values are keyed by account; a new session-wide lever's value is shared when its native home is, as settings.json is. Surface only levers that are genuinely new — never re-recommend anything on the exclusion list in levers.md.
5. **Update the table**: rows, options, cost and impact figures, and the `Last updated` date. List each type's options from most expensive to cheapest, so every step down is a step cheaper; mark an option dominated when another costs no more and scores higher. Show the user the levers.md diff before writing — the table drives every future recommendation.
