# Hillclimb

Sustained, scientific improvement of one metric against a target: loop hypotheses with before and after measurement, a decision log, and one commit per accepted win. Distinct from the [perf](perf.md) recipe, which is a one-off fix.

**You own the metric and the experiment's integrity. Supervise and review. Delegate the attempts.** For sustained, iterative improvement of one measurable thing against a target. A one-off fix is the [bug fix](bug-fix.md) or perf recipe. This is the loop.

Core discipline: one change, one measurement, keep or revert. Never stack untested changes, and never claim a win from code inspection (the [prove it works](../../../dependencies/principles/prove-it-works.md) principle).

1. Ground the workload and architecture before choosing the metric. Run the [how](../stations/how.md) station over the target, name the realistic workload dimensions that can move the result (data size, history, state, concurrency), and select a case that reproduces the user's complaint. If no case reproduces it, fix the repro instead of hillclimbing. Then fix one metric, the direction that counts as better, and a checkable stop predicate that pairs a target with a floor on attempts so a lucky early win can't end the run (the example "at least 50% better than baseline and at least 10 iterations" is this shape). Use the user's numbers when given, an order's done-when included. Otherwise agree them with the user, and headless, set them per [SKILL.md](../../../SKILL.md#autonomy).
2. Build the measurement harness, prove its sensitivity, then freeze it (the [build the lever](../../../dependencies/principles/build-the-lever.md) principle). Run contrasting realistic workloads and confirm the target case reproduces the symptom while easier cases separate as expected. If the harness cannot distinguish them, revise the workload or metric. Vet the harness with the [benchmark checklist](../stations/benchmark-checklist.md) station before you freeze it, and make it print its error count and a count of the work done. Freezing it is its [contract](../stations/contract.md) commit, which no delegate may touch. Once frozen, one repeatable command emits the metric, sampled enough to clear the noise (median of N, not a single run). Record the baseline metric and a green run of the regression gate (the tests that must keep passing) before any change.
3. Open the decision log via the [show me your work](../stations/show-me-your-work.md) station. One row per attempt: its id as the phase, the change as the decision, the hypothesis as the why, before, after, and delta as the evidence, and kept or reverted as the result. Read it before each attempt. Keep it out of the tree (git-ignored).
4. Ground each hypothesis in the architecture model from step 1, so it names a specific mechanism ("defer X off the boot path because it blocks first paint"), not "try memoizing something". For a perf metric, order hypotheses by the performance mantras in step 2 of the perf recipe. Borrow only their order, not that step's stop rule.
5. Loop, one hypothesis per iteration:
   - Hand the change to a `worker-agent` on the code role ([SKILL.md](../../../SKILL.md#subagents)) with a tight scope. Supervise and review the diff rather than typing it (the [guard the context window](../../../dependencies/principles/guard-the-context-window.md) principle). When several independent hypotheses are live, fan them to parallel subagents, each in its own worktree (`isolation: "worktree"`, the [separate before serializing shared state](../../../dependencies/principles/separate-before-serializing-shared-state.md) principle).
   - Measure before and after with the frozen harness, and run the regression gate.
   - Accept only when the metric moves past noise and the gate stays green. Otherwise revert the change in full. A tweak that "might help" is not kept.
   - One commit per accepted fix, staging only the files you changed (`git add <files>`, never `-A`). Log the row either way, kept or reverted.

   Each iteration ends in a check before the next begins (the [sequence verifiable units](../../../dependencies/principles/sequence-verifiable-units.md) principle). If the run is unattended, borrow only the wake mechanism from the [autonomous run](autonomous-run.md) recipe, not its stop rule.
6. Push past the first plateau. On a stall, several rejects in a row, pivot category, combine near-misses, re-read the source, or try something more radical before concluding the hill is climbed. Correctness and simplicity outrank the number. Revert a win that breaks behavior, and keep a simplification that holds the number (the [laziness protocol](../../../dependencies/principles/laziness-protocol.md) principle).
7. Stop when the predicate is met, or when the remaining ideas are marginal and not worth their cost. Don't relax the predicate to meet it, and don't quit while cheap untried hypotheses remain. If you are stuck, surface it instead of spinning.
8. Run the [open a PR](open-a-pr.md) recipe, the accepted commits in the order they landed.

**Reply:** the metric and target, baseline to final with the percent delta, iterations run (kept vs reverted), each accepted fix on one line, the decision log's path, and the best idea you would try next if pushed further.
