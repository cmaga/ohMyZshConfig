# Refactor

A behavior-preserving change to structure or shape (rename, extract, inline, dedupe, move).

**You own the contract. The structure changes. The behavior does not.** Distinct from the [feature](feature.md) recipe, which adds behavior, and the [bug fix](bug-fix.md) recipe, which corrects it.

If the cleanup reveals a missing feature or a real bug, split it out and ship the structural change first against the pinned contract. A redesign is allowed, but name it and route to the feature recipe. Large or cross-cutting structural work belongs to the [figure it out](../stations/figure-it-out.md) station. This recipe is the focused-to-medium change.

1. Pin the behavior contract first. Run the [how](../stations/how.md) station over the affected subsystem to learn the contract, then have a characterization test, snapshot, or equivalence harness that captures current behavior written and locked per the [contract](../stations/contract.md) station before any structure moves. If the area has no coverage, write the pin before touching structure. Type check and lint are not a pin.
2. Name the structure the code is missing per the [model the domain](../../../dependencies/principles/model-the-domain.md) principle. Boring code stays when the shape is already clear and local. The reshape must delete branches or invalid states, not add indirection.
3. Name the target shape. State what the module layout, types, and call graph should be if built today (the [foundational thinking](../../../dependencies/principles/foundational-thinking.md) and [redesign from first principles](../../../dependencies/principles/redesign-from-first-principles.md) principles). If the target crosses a function boundary, run the [architect](../stations/architect.md) station for parallel design exploration of the shape before the move.
4. Subtract before you add. Delete dead code, collapse one-caller wrappers, drop redundant validators, and remove orphan references before introducing the new shape (the [subtract before you add](../../../dependencies/principles/subtract-before-you-add.md) principle). The smallest change that reaches the target shape ships (the [laziness protocol](../../../dependencies/principles/laziness-protocol.md) principle). A speculative cleanup that "might help" gets reverted.
5. Move in small behavior-preserving steps, each keeping the pin green. For API reshapes, migrate every caller and delete the old API in the same wave (the [migrate callers then delete legacy APIs](../../../dependencies/principles/migrate-callers-then-delete-legacy-apis.md) principle). No compatibility shims, no parallel old-and-new paths. Spot-check every rename against the actual files. Renames silently miss usages in strings, prose, and back-references. Delegate the mechanical edits to a `worker-agent` on the code role ([SKILL.md](../../../SKILL.md#subagents)) with a specific scope (file paths, the names being moved, the contract files and their `Contract-Run` command).
6. Prove behavior is unchanged on the real artifact, not "it compiles" (the [prove it works](../../../dependencies/principles/prove-it-works.md) principle). For larger reshapes, run an equivalence check: a script that diffs old-vs-new outputs, a recorded baseline replayed against the new code, or a smoke run on the matching surface through the project's verify skill (`.claude/skills/verify*`).
7. Confirm the change is worth keeping. The success measure is reduced reader load (the [minimize reader load](../../../dependencies/principles/minimize-reader-load.md) principle). If the diff does not lower reader load somewhere, revert it.
8. Rebase into small ordered commits. A subtraction commit, then the reshape, then any follow-on cleanup. Shape them with the [sequence verifiable units](../../../dependencies/principles/sequence-verifiable-units.md) principle, so each behavior-preserving slice stays green before the next.
9. Run the [open a PR](open-a-pr.md) recipe.

**Reply:** the structure that changed, the pin you held it against, the equivalence proof, the reader-load delta, what shipped and what got reverted. No new behavior.
